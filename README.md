# 商圏分析マップ (OSM / Leaflet版)

`gis_drive_analysis.md` で解析した「GIS DRIVE」の機能をベースに、
Google Maps の代わりに **OpenStreetMap + Leaflet** で構築した商圏分析ツールです。
`boundaries/` フォルダの町丁目・字境界データ(全国、KEY_CODE付き)を使って、
選択した商圏範囲に含まれる実際の町丁目・字の境界線を描画します。

## 使い方

### 1. ローカルサーバーを起動する(必須)

`boundaries/` は全国327MBあるため、選択範囲に応じて必要なファイルだけを
その都度 `fetch()` で読み込みます。ブラウザは `file://` で開いたページからの
`fetch()` をセキュリティ上ブロックするため、**ローカルサーバー経由で開く必要があります**
(`index.html` をダブルクリックするだけでは町丁目境界・検索・統計データ読み込みが動作しません)。

```bash
# このフォルダ(GISドライブ)で実行
python -m http.server 8000
```

ブラウザで `http://localhost:8000/index.html` を開いてください。

### 2. 操作方法

1. 左パネルで地点を検索するか、地図を直接操作して商圏を指定したいエリアまで移動。
2. 「商圏の指定方法」から形状を選択:
   - **円形**: 地図をクリックして中心を指定 → スライダーで半径(100〜5000m)を調整。
   - **多角形**: 地図上をクリックして頂点を追加 → 始点付近をクリック、またはダブルクリックで確定。「一つ戻す」で直前の頂点を取り消し。
   - **所要時間**: 移動手段(徒歩/自転車/車)と分数を指定し、地図をクリックして起点を指定。
     - [OpenRouteService](https://openrouteservice.org/dev/#/signup) の無料APIキーを入力すると、実際の道路網に基づく等時間圏(isochrone)を取得します。
     - 未入力の場合は「速度 × 時間」による近似円で代替表示します(実際の道路事情は反映されません)。
   - **地域**: 表示されている町丁目・字の境界をクリックして複数選択。地図を動かすと表示範囲の境界が自動で読み込まれます。
3. いずれの方法でも、選択範囲と交差する**実際の町丁目・字境界線**が地図上に描画され、含まれる世帯数(境界データの `SETAI` 属性)が自動集計されます。
4. 「条件を選択」ボタンで属性条件(性別年代・婚姻・家族構成・住居・年収・貯蓄)を絞り込み、集計結果・ランク別色分けを確認。
5. 「画面をレポート画像として保存」で、現在の画面(パネル+地図)をPNG画像としてダウンロード。

範囲を広げすぎて対象市区町村が多くなりすぎた場合(目安12市区町村超)は、フリーズを防ぐため
読み込みを行わず「範囲が広すぎます」と表示します。その場合は地図を拡大するか、選択範囲を狭めてください。

## 町丁目・字境界データ (`boundaries/`)

- 構成: `boundaries/{都道府県コード2桁}/{市区町村コード5桁}.geojson` + 都道府県ごとの `index.json`(市区町村一覧)。
- 各 `Feature` の主な `properties`:
  | フィールド | 内容 |
  |---|---|
  | `KEY_CODE` | 町丁目・字を一意に識別するコード(属性データとの結合キー) |
  | `PREF` / `CITY` | 都道府県コード / 市区町村コード |
  | `CITY_NAME` | 市区町村名 |
  | `S_NAME` | 町丁目・字名 |
  | `SETAI` | 世帯数(このアプリの世帯数集計はこの値をそのまま使用) |
- 起動時に `data/boundaries_index.json`(各市区町村ファイルのbboxのみをまとめた軽量インデックス、約250KB)を読み込み、
  選択範囲のbboxと交差する市区町村ファイルだけを [js/boundaryLoader.js](js/boundaryLoader.js) が遅延読み込み・キャッシュします。
- `boundaries/` の中身を差し替えた場合は、インデックスの再生成が必要です:
  ```bash
  python scripts/build_boundaries_index.py
  ```

## 属性データ(性別年代・年収などの内訳)について

世帯数・ジオメトリは `boundaries/` から自動的に得られますが、その内訳(性別年代・婚姻・家族構成・
住居形態・年収・貯蓄)は含まれていません。起動直後は [data/sample_stats.js](data/sample_stats.js) の
**デモ用ダミーデータ**(千代田区の実在するKEY_CODEに対して疑似生成した内訳)が読み込まれています。

実際の属性データが提供され次第、左パネルの「属性データ読み込み」から差し替えてください
(ファイルはブラウザ内で処理され、外部送信されません)。

### 期待するJSONスキーマ

`boundaries/` の `KEY_CODE` をキーにした配列形式(ジオメトリは不要):

```jsonc
[
  {
    "key_code": "011010200",        // boundaries側の KEY_CODE と一致させる
    "population": 320,               // 任意。無ければ人口集計は0のまま
    "segments": {
      "sexage":   { "male_20s": 12, "female_20s": 10, ... },
      "marriage": { "single": 40, "married": 60 },
      "family":   { "single_person": 30, "couple": 20, ... },
      "housing":  { "owned_house": 40, "rented_apartment": 50, ... },
      "income":   { "under300": 20, "300_500": 30, ... },
      "saving":   { "under100": 25, "100_500": 40, ... }
    }
  },
  ...
]
```

- カテゴリ・選択肢のキー名は [js/config.js](js/config.js) の `SEGMENT_CONFIG` と一致させてください。
  実データのカテゴリ構成が異なる場合は `SEGMENT_CONFIG` を編集すれば、UI・集計ロジックとも自動的に追従します。
- `segments` 以下のカテゴリ・`key_code` に対応するレコード自体も省略可能です(その場合は絞り込み条件として無視され、世帯数の絞り込みは行われません)。

### 属性条件による絞り込みの考え方

選択した属性条件(例:「女性20代」かつ「未婚」)に完全一致する世帯数を直接持っているわけではないため、
各カテゴリ内の

```
選択した選択肢の合計 ÷ カテゴリ全体の合計
```

を比率とし、複数カテゴリにまたがる場合はこれらの比率が独立事象であるとみなして掛け合わせることで
世帯数を **推定** しています。実際の世帯構成には相関があるため、あくまで概算値である点にご注意ください
(この前提は左パネルにも注記しています)。真の交差集計データをお持ちの場合は、
`segments` の下に交差済みのカテゴリ(例: `sexage_x_income` など)を追加し、
[js/dataStore.js](js/dataStore.js) の `estimateHouseholds` を該当カテゴリ優先で参照するよう調整することで、
より正確な集計に切り替えられます。

## ファイル構成

```
index.html               エントリポイント
css/style.css             スタイル
js/config.js               セグメント条件・配色などの設定
js/dataStore.js            属性データ(KEY_CODEキー)の保持・集計ロジック
js/boundaryLoader.js       町丁目・字境界データの遅延読み込み・キャッシュ
js/map.js                  Leaflet地図・検索・商圏図形描画・境界ポリゴン表示
js/panel.js                 左サイドパネルのUI制御
js/report.js                html2canvasによるレポート画像出力
js/main.js                  全体の結線・非同期読み込みフロー・集計
data/sample_stats.js        デモ用ダミー属性データ
data/boundaries_index.json  境界データの軽量bboxインデックス(build_boundaries_index.pyで生成)
scripts/build_boundaries_index.py  上記インデックスの生成スクリプト
boundaries/                 町丁目・字境界データ本体(都道府県×市区町村のGeoJSON)
```

## 使用ライブラリ (すべてCDN経由・無料)

| ライブラリ | 用途 |
|---|---|
| Leaflet | 地図表示 |
| OpenStreetMap タイル | ベースマップ |
| Esri World Imagery | 航空写真(切替表示用) |
| Nominatim (OpenStreetMap) | 住所・地名検索(ジオコーディング) |
| Turf.js | 図形の交差判定・バッファ計算 |
| html2canvas | 画面キャプチャ(レポート出力) |
| OpenRouteService (任意) | 所要時間モードの道路網ベース等時間圏 |
| Font Awesome | アイコン |

## 元アプリとの主な違い

- ログイン機能は実装していません(サーバーを持たないクライアント完結アプリのため)。
- レポートのメール送信機能は実装していません(バックエンドが必要なため)。画像ダウンロードのみ対応。
- 「所要時間」商圏は、APIキー未設定時は近似円になります(元アプリのような道路網ベースの正確な等時間圏を無償で得るには外部ルーティングAPIが必要です)。
- 属性セグメントの絞り込みは上記の通り独立仮定に基づく推定値です。
- `fetch()` を使用するため、`index.html` を直接開く(`file://`)のではなく、ローカルサーバー経由で開く必要があります。
